# Обязательные разделы диспетчерской панели

Источник: письмо с темой «скрин» от 27 мая 2026 года. В письме находятся 12 эталонных экранов прежней панели Aqua Delivery. Персональные данные со скриншотов в этот документ не переносятся.

## Обязательный состав

| Раздел | Обязательные элементы | Текущее состояние |
| --- | --- | --- |
| Заказы | Таблица, дата доставки, интервал, состав, водитель, статус, фильтры, сортировка, экспорт, новый заказ | Реализовано; экспорт CSV и рабочие фильтры добавлены |
| Маршрутные листы | Неразобранные, назначенные и недоставленные заказы; группировка по району и интервалу; назначение водителя | Реализовано на текущих заказах |
| Клиенты | ФИО, адрес, телефон, email, статус, баллы, долг по таре, число заказов, последний заказ, оценка | Реализован отдельный справочник с заполнением из заказов и импорта |
| Организации | Название, ИНН, КПП, телефон, email, адрес, долг по таре | Реализован отдельный справочник с заполнением из договорных заказов и импорта |
| Адреса | Клиент, зона/район, адрес, координаты, фильтр адресов без координат | Реализован отдельный справочник с заполнением из заказов и импорта |
| Водители | ФИО, телефон, рабочий статус, машина, нагрузка, выполненные заказы, продажи по способам оплаты, бутылки и тара | Реализовано; добавлена дневная сводка и учёт остатков в машине |
| Оповещения | Хронология изменений по заказам | Реализовано из `order_events` |
| Чат | Список сообщений и карточка диалога | Системные сообщения реализованы из `order_events`; двусторонняя переписка требует провайдера сообщений |
| Обратная связь | Клиент, заказ, оценка, водитель, дата | Реализовано из `client_ratings` |
| Микромаркеты | Отдельный раздел контроля вендинговых точек | Раздел добавлен; реестр аппаратов требует отдельного источника данных |
| Импорт | Перенос клиентов, адресов, организаций и заказов от предыдущего поставщика | CSV, XLSX и JSON; предварительная проверка, пакетная обработка и журнал доступны только администратору |
| Диспетчерская | Оперативная карта заказов и водителей, прогресс маршрутов, загрузка и центр проблем | Реализовано; проблемы можно принять в работу и закрыть с комментарием |
| Закрытие смен | Сверка денег, бутылок, тары и пробега; блокировка закрытого дня | Реализовано; повторное открытие доступно только администратору с обязательной причиной |
| Аналитика | KPI, динамика, способы оплаты, водители, зоны, качество данных и сравнение периодов | Реализовано для периода до 366 дней |
| Журнал контроля | Автор, время, раздел, действие и значения до/после | Реализовано для критичных операционных сущностей |

## Дополнительное согласованное требование

- Карта зон доставки находится отдельно от маршрутных листов.
- Администратор может создавать, менять и удалять зоны.
- Диспетчер может только просматривать зоны и их настройки.
- Для каждой зоны администратор может включить автокоррекцию по статистике подтверждённых доставок.
- Новый адрес автоматически включается в ближайшую зону только после заданного числа повторов за выбранный период и при соблюдении максимального расстояния от границы.
- Автоматическое расширение сохраняется в журнале обучения, отображается на карте и может быть отменено администратором, если после него границу не редактировали вручную.
- В панели ведётся реестр автомобилей по уникальным государственным номерам, марке, модели, цвету и техническому состоянию.
- Администратор добавляет и редактирует автомобили; администратор и диспетчеры назначают активного водителя на готовую к работе машину.
- Одновременно у автомобиля может быть только один водитель, а у водителя — только один автомобиль; вся история назначений сохраняется.
- Перевод автомобиля на обслуживание или вывод из эксплуатации автоматически снимает текущее назначение без удаления истории.
- Для каждого водителя за выбранный день автоматически считаются количество заказов и сумма продаж по наличным, терминалу, QR-коду, онлайн-оплате и договору.
- Способ оплаты берётся из подтверждения водителя по выполненной доставке, а до подтверждения — из запланированного способа заказа.
- По выполненным заказам автоматически считаются реализованные полные бутылки и собранная у клиентов пустая тара.
- Администратор и диспетчер вносят загрузку перед рейсом, начальную тару и фактическую выгрузку на склад; водитель не может менять эти значения.
- Остаток полных бутылок в машине считается как «загружено − реализовано − выгружено», а остаток тары — как «тара на начало + собрано − выгружено».
- Если загрузка не заполнена, панель не подставляет фиктивный ноль; отрицательный остаток отображается как расхождение для проверки диспетчером.
- Мобильное приложение передаёт последнюю GPS-точку водителя при штатном обновлении местоположения; ошибка передачи не блокирует работу водителя.
- Оперативный экран выделяет неназначенные, опаздывающие и недоставленные заказы, отсутствие координат, устаревшую GPS-точку, нехватку загрузки и отрицательные остатки.
- Закрытие смены возможно только после завершения активных заказов и заполнения загрузки/выгрузки автомобиля.
- После закрытия смены изменение заказов и складских значений этого водителя за день блокируется на уровне базы.
- Любое расхождение фактических денег, полных бутылок или тары требует комментария диспетчера.
- Повторно открыть закрытую смену может только администратор; причина и значения до/после сохраняются в журнале контроля.
- Движение полных бутылок и тары записывается знаковыми операциями без стирания предыдущей истории.
- Клиентские сообщения формируются в очереди автоматически. До подключения SMS или мессенджер-провайдера они честно отображаются как ожидающие подключения, а не как отправленные.

## Импорт предыдущего поставщика

- Клиенты и организации повторно сопоставляются по телефону, email, ИНН или исходному идентификатору.
- Заказы с уже существующим номером или исходным идентификатором не перезаписываются.
- Известные поля записываются в рабочие справочники, а полная исходная строка сохраняется в `legacy_data` для сверки.
- Сам загруженный файл не хранится. В журнале остаются имя файла, источник, контрольная сумма, итоговые счётчики и до 100 ошибок.
- Открывать страницу импорта и запускать перенос может только пользователь с ролью `admin`.
- Для новых запусков записывается точный журнал созданных и обновлённых строк. Администратор может отменить импорт, если после него данные не редактировались; при обнаружении более новых правок отмена полностью останавливается.
